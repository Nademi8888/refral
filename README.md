# RaGNaR GEM — نسخه ۲ (نصب آسان + Railway)

ربات جم رایگان فری‌فایر با سیستم رفرال، حالا با **ویزارد نصب تحت وب** و **دیپلوی یک‌مرحله‌ای روی Railway** — دقیقاً همان الگویی که فاکسیما دارد، ولی برای پروژه‌ی پایتونی.

نسخه قبلی برای هر تنظیم، نیاز به دست زدن به `config.py` و ست کردن دستی متغیرها داشت. حالا:

- سرویس روی Railway بالا می‌آید و روی آدرس عمومی، صفحه‌ی نصب را نشان می‌دهد.
- اتصال MySQL ریلوی **خودکار** تشخیص داده می‌شود (`MYSQL_URL`, `MYSQLHOST`, …).
- توکن، ادمین، کانال‌ها و مقادیر جم از داخل فرم گرفته می‌شود و **در دیتابیس** ذخیره می‌شود، پس با هر دیپلوی دوباره باقی می‌ماند.
- بعد از نصب، ربات بدون ری‌استارت دستی شروع به کار می‌کند و پنل مدیریت فعال می‌شود.

---

## دیپلوی روی Railway

۱. این پوشه را روی یک ریپازیتوری گیت‌هاب پوش کنید.

۲. در Railway: `New Project → Deploy from GitHub repo` و همین ریپو را انتخاب کنید. Dockerfile خودکار build می‌شود.

۳. در همان پروژه: `+ New → Database → Add MySQL`.

۴. روی سرویس ربات → تب **Variables** → `Add Variable Reference` → متغیرهای MySQL را وصل کنید (یا فقط `MYSQL_URL`). چیز دیگری لازم نیست.

۵. تب **Settings → Networking → Generate Domain** تا یک آدرس عمومی بگیرید.

۶. آدرس را در مرورگر باز کنید؛ ویزارد نصب می‌آید:
   - مرحله ۱: بررسی سرور و دیتابیس
   - مرحله ۲: توکن ربات، آیدی ادمین، کانال‌ها، تعداد رفرال و جم
   - مرحله ۳: لینک پنل مدیریت — **آن را ذخیره کنید**

۷. تمام. ربات فعال است.

### اگر می‌خواهید بدون ویزارد نصب شود

کافی است در Variables مقادیر زیر را بگذارید؛ سرویس در همان بوت اول خودش راه می‌افتد:

```
BOT_TOKEN=...
ADMIN_ID=...
```

باقی مقادیر (`CHANNEL_2`، `REFERRALS_REQUIRED`، `GEMS_PER_WITHDRAWAL` و …) در `.env.example` آمده و اختیاری است.

### امنیت صفحه نصب

تا وقتی نصب انجام نشده، آدرس عمومی سرویس صفحه‌ی نصب را نشان می‌دهد. اگر می‌خواهید قبل از نصب هم قفل باشد، متغیر `INSTALL_KEY` را با یک رشته‌ی تصادفی ست کنید و صفحه را با `?key=همان-رشته` باز کنید. بعد از نصب، صفحه‌ی نصب به‌صورت خودکار بسته می‌شود.

## پنل مدیریت

`https://your-app.up.railway.app/panel?key=...`

- آمار زنده: کاربران، رفرال فعال، برداشت در انتظار/پرداخت‌شده، مجموع جم
- تغییر توکن، ادمین، کانال‌ها، تعداد رفرال و جم بدون دیپلوی مجدد
- دکمه ری‌استارت ربات

کلید پنل در `data/config.json` ساخته می‌شود. اگر لینک را گم کردید، در Deploy Logs خط `پنل مدیریت: /panel?key=...` را ببینید.

## ساختار پروژه

```
main.py                 اجرای وب‌سرور + ربات در یک پراسس
app/settings.py         مدیریت تنظیمات (متغیر محیطی، فایل، دیتابیس)
app/database.py         لایه دیتابیس؛ MySQL با pool، fallback روی SQLite
app/bot.py              منطق ربات و کنترل start/stop/restart
app/server.py           API نصب‌کننده و پنل + health check
app/static/*.html       رابط فارسی و راست‌چین ویزارد و پنل
Dockerfile              ایمیج python:3.12-slim
railway.json            تنظیم build و healthcheck ریلوی
```

## چه چیزهایی نسبت به نسخه قبل اصلاح شد

- **دو هندلر هم‌پوشان متن** (`text_handler` و `admin_text` در گروه‌های مختلف) به یک هندلر تبدیل شد؛ قبلاً پاسخ ادمین به کاربر گاهی اجرا نمی‌شد.
- **کرش روی کاربر ناشناس**: `get_user` اگر خالی برمی‌گشت، `r[4]` خطا می‌داد. حالا پیام «/start را بزنید» داده می‌شود.
- **جم واریزی** از روی رکورد برداشت خوانده می‌شود، نه مقدار لحظه‌ای تنظیمات؛ اگر مقدار جم عوض شود، برداشت‌های قدیمی درست می‌مانند.
- **کسر رفرال** دیگر عدد ثابت ۱۱۰ را هاردکد نمی‌کند.
- **باز شدن اتصال جدید برای هر کوئری** حذف شد و جای آن استخر اتصال با `ping(reconnect=True)` آمد؛ روی ریلوی اتصال MySQL بی‌کار قطع می‌شود و این جلوی خطاهای «server has gone away» را می‌گیرد.
- کوئری‌های دیتابیس با `asyncio.to_thread` اجرا می‌شوند تا حلقه‌ی ربات بلاک نشود.
- `/broadcast` بین هر ۲۰ پیام مکث می‌کند تا محدودیت ارسال تلگرام نخورد.
- کانال اجباری `@kodisavpn` همچنان هاردکد است و نه از پنل و نه از متغیرها قابل حذف نیست.

## اجرای محلی

```bash
pip install -r requirements.txt
cp .env.example .env     # مقادیر را پر کنید (اختیاری)
python main.py           # http://localhost:8080
```

بدون تنظیم دیتابیس، ربات روی SQLite بالا می‌آید. روی Railway از SQLite استفاده نکنید؛ دیسک آن موقتی است و با هر دیپلوی داده‌ها پاک می‌شود.
